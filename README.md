Implementation and captures prepared by GPT 6.1 Sol through the Codex harness in T3 Code.

`noIndentedCodeBlocks` defaults to `false`. With the option enabled, four-space or tab-indented content parses as normal Markdown. Backtick and tilde fenced blocks remain code. The native shells use the real shared parser and native renderers.

## Reproduction

Use a disposable checkout at the base or after revision, Node 22.20.0 and repository-pinned Yarn 4.11.0. Run `yarn install --immutable` and `yarn prepare`. Apply the matching `setup-base.patch` or `setup-head.patch` with `git apply`. These patches replace only the two standalone example entry files. The full fixture source is also included separately for each platform/revision.

Build iOS from `apps/ios-example`, substituting the selected simulator's UDID:

```sh
xcodebuild -project EnrichedMarkdownExample/EnrichedMarkdownExample.xcodeproj \
  -scheme EnrichedMarkdownExample \
  -destination "platform=iOS Simulator,id=$IOS_SIMULATOR_UDID" \
  -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
```

Build Android from `apps/android-example` with JDK 17 and Android SDK configured:

```sh
./gradlew :app:assembleDebug --no-daemon --console=plain --max-workers=2
```

Install the resulting native example app on the chosen device. The base shell opens with default parsing. On the after shell, toggle "Render indented prose" on, then off. Keep the same device and appearance for each platform's pair. Avoid overlapping Gradle builds of the same checkout. The final sequential Android after build also used `-Pkotlin.incremental=false` after an incremental-cache collision during setup.

## Validation and limits

- New native prop-normalization tests fail against unchanged upstream normalization because the flag is absent. The new WASM opt-in assertion fails against the unchanged committed bundle, finding three code blocks instead of the expected two. Both pass with the feature.
- Shared parser regression covers omitted/false/true settings, spaces, tabs, list and blockquote nesting, both Markdown flavors, both fences and repeated off/on/off parsing. Existing 25 golden AST combinations, symbol isolation and upstream-MD4C coexistence checks pass.
- Rebuilt WASM passes all 10 existing exported golden combinations and the new actual opt-in behavior check. Its committed artifact is in the production PR; React Native codegen outputs were regenerated by prepare and remain ignored under repository policy.
- Jest: 18 suites, 113 tests pass.
- Standalone iOS: 664 tests, nine skipped, zero failures. React Native iOS: 23 tests pass, including option copying, measurement-cache separation, both streaming-invalidation directions and normal/segmented measurement returning to the default size. The test target now matches the app's C++20 setting so these tests can use real generated props.
- Standalone Android: 636 unit tests pass. React Native Android: 32 unit tests and ktlint pass. The feature-named parser instrumentation test passes through JNI on Android 15.
- Typecheck, source ESLint, core/changed-source clang-format, docs production build and commit hooks pass. Source ESLint retains one existing inline-style warning. After native tests generate report.js files, root lint needs `--ignore-pattern '**/build/**'`. The broad clang script also visits ignored generated Props.h and reports formatting there; generated files were not hand-edited.
- Maestro: the new toggle flow passes syntax checking. Its assertions are scoped to preview-container so the editor cannot satisfy them. The Android Maestro driver timed out before executing the flow. The full Maestro suites and iOS Maestro flow have not run. Direct device verification is separate from a passing Maestro result.

Commands used include `scripts/test-core-parser.sh`, `node scripts/test-web-bundle.mjs`, `yarn test --runInBand`, `yarn typecheck`, `yarn lint --ignore-pattern '**/build/**'`, `yarn lint-clang:core-parser`, the native package test scripts and `yarn test:ios` in the React Native example. JNI instrumentation used `:parser:assembleDebugAndroidTest` and the feature-named AndroidJUnitRunner test on the selected emulator. `yarn install --immutable` and `yarn build` passed inside docs.

The machine's global Corepack launcher misclassified its cached Yarn entry point as ESM. Successful invocations used the repository-pinned `node .yarn/releases/yarn-4.11.0.cjs ...`, including a temporary local wrapper for nested scripts. This did not change the repository.
